fix(figjam): plugin-side Replace + render cache + rate-limited Live toggle

User report: replace duplicated/placed instead of rewriting the selected node
(the old flow guessed ids on the mirror and could hit the wrong copy — e.g.
an existing Penpot copy got "synced" instead of the selected image), and 4
replaces burned the Figma rate limit.

- figjam-replace: the PLUGIN reads figma.currentPage.selection at message
  time and rewrites those nodes in place (fills, size, crop transform,
  plugin meta to the new key). No mirror<->plugin id round-trip, so tracked
  mirrors and hand-placed/foreign images behave identically and the "wrong
  copy" case disappears. With no selection it degrades to normal placement.
- Render cache (90s TTL): Import/Replace/Sync of the same frame+scale+format
  reuse the last data-URL — 4 replaces of one frame = 1 Figma Render call,
  killing the fast rate-limit exhaust. Penpot exports cached at 120s.
- Live Figma selection checkbox greys out ("Paused — Figma is
  rate-limiting") while a 429/cooldown is active and auto-re-enables ~20s.

Test: tsc clean, lint 0 errors, 138/138. Local yarn build still blocked by
the pre-existing Next 16 workStore prerender invariant (Node 24, unrelated
routes); CI builds with Node 20.
